# ארכיטקטורה

## עקרונות

- **מצב נגזר, לא מוקלד.** סטטוס של כל שלב (Not Started … Completed) מחושב מהתוצרים, האישורים, המשימות והחסמים (`server/src/workflow/state.ts`, פונקציה טהורה). אין "סטטוס" שאפשר לשכוח לעדכן.
- **פקודות עם Gates.** כל פעולת משתמש עוברת ב-`workflow/commands.ts`, שבודק את נקודת האישור לפני שינוי. לדוגמה: אי אפשר לסמן אישור לקוח לפני אישור פנימי, ואי אפשר ליצור סטורי בורד לפני אישור לקוח על הגרסה האחרונה.
- **Event → Rule → Job.** כל שינוי נרשם כ-Event, שהוא גם היסטוריית הפעילות. `workflow/rules.ts` הוא המקום היחיד שבו מוגדר "מה מפעיל מה", וכל כלל מגיב רק לאירוע אישור מפורש.
- **אמת על אינטגרציות.** כל תוצר נושא את המקור שלו: `ai` / `ai_revision` / `manual` / `demo` / `skeleton`. הממשק מסמן *אוטומטי* / *ידני* / *DEMO* / *טרם נבנה*. משימה מסומנת "הצליחה" רק אחרי שהתוצר נשמר בפועל.
- **לא מוחקים תוצרים.** הרצה חוזרת יוצרת גרסה חדשה (תסריט: `script_versions`; סטורי בורד: גרסה קודמת → `superseded`, לקריאה בלבד).

## שכבות

```
web (React)                         ממשק משתמש
  │  REST /api
server/api/routes.ts                 ניתוב HTTP + אימות קלט (zod)
server/workflow/commands.ts          ניהול פרויקטים ושלבים + מנגנון האישורים (Gates)
server/workflow/events.ts, rules.ts  Event bus + כללי אוטומציה
server/workflow/queue.ts             תור Jobs עמיד עם מניעת כפילויות
server/jobs/worker.ts, handlers.ts   Worker: הרצה, Retry, זיהוי תקועים
server/workflow/state.ts             גזירת מצב פרויקט (סטטוסים, התקדמות, פעולה הבאה, חסמים)
server/providers/*                   ספקי מודלים (ממשק TextProvider; OpenAI, Demo)
server/services/notifications.ts     התראות (בתוך האפליקציה; הדפדפן מציג Web Notifications)
server/db/*                          SQLite (node:sqlite), מיגרציות, Repository
```

## מנגנון ה-Jobs

| דרישה | מימוש |
| --- | --- |
| מניעת משימות כפולות | `idempotency_key` ייחודי (נגזר מה-Event), ובנוסף אין שתי משימות פעילות מאותו סוג לפרויקט |
| Retry | שגיאות זמניות (429, 5xx, רשת, פלט שנקטע) נוסות שוב עם backoff מעריכי, עד `JOB_MAX_ATTEMPTS` |
| שגיאות קבועות | מפתח חסר, 401, אין קרדיט, מודל לא קיים, סירוב: המשימה נכשלת מיד והשלב מסומן **חסום** עם הסיבה |
| לוג ניסיונות | `job_attempts`: התחלה, סיום, הצלחה ושגיאה לכל ניסיון |
| משימות תקועות | `running` בלי heartbeat מעבר ל-`STUCK_JOB_MINUTES` חוזרת לתור; בהפעלת השרת כל משימת `running` מטופלת כנקטעה |
| פרויקט תקוע | אין התקדמות במשך `STALLED_PROJECT_DAYS`: נרשם חסם ונשלחת התראה; כל התקדמות חדשה מסירה אותו |
| עצירה / השהיה | `paused`: המשימות נשארות בתור. `stopped`: משימות פעילות מבוטלות, ותוצאה של משימה שבוטלה באמצע ריצה לא נשמרת |
| הרצה חוזרת | ניסיון חוזר ידני יוצר משימה חדשה (הלוג של הקודמת נשמר); "טיוטה חדשה" או "גרסה חדשה" לא מוחקות תוצרים |

## ספקים (Providers)

`TextProvider` (`server/providers/types.ts`) הוא ממשק אחיד: `generateScript`, `reviseScript`, `generateStoryboard`.
ספק חדש (למשל Claude או Gemini) מוסיפים כמחלקה שמממשת את הממשק ורושמים ב-`providers/registry.ts`, בלי שינוי בשאר המערכת.

- **OpenAI**: Chat Completions עם `response_format: json_schema` (strict), כך שהתסריט והשוטים נשמרים כנתונים מובנים. המודל נבחר ב-`.env` וניתן לדריסה לכל פרויקט.
- **Demo**: תוכן תבניתי ללא AI, לבדיקת הזרימה בלבד. מסומן `DEMO` בכל מקום.

ספקי תמונה והנפשה (Phase 3–4) ייבנו באותה תבנית: ממשק אחיד, ולכל ספק דגל `automatic` או `manual`. כשאין API נתמך, ייווצר כרטיס משימה ידני עם פרומפט מוכן והעלאת התוצאה.

## מודל נתונים (SQLite)

`projects` (בריף והגדרות כ-JSON) · `script_versions` · `storyboards` · `shots` · `refs` · `approvals` (מי, מה, מתי, פנימי או לקוח) ·
`comments` · `events` · `jobs` · `job_attempts` · `notifications` · `blockers` · `assets`.

מיגרציות: `server/db/schema.ts`. לעולם לא משנים מיגרציה קיימת, רק מוסיפים חדשה.

## אבטחה

- מפתחות API ב-`.env` בצד השרת בלבד. הקובץ מוחרג ב-`.gitignore`.
- השרת מאזין כברירת מחדל ל-`127.0.0.1` בלבד. אין עדיין מנגנון התחברות, כי זו מערכת אישית ומקומית. לפני חשיפה לרשת צריך להוסיף אימות.
- חיפוש רפרנסים מתבצע בקישורים לחיפוש בפלטפורמה עצמה (בלשונית חדשה). אין סריקה (scraping), ואין עקיפה של התחברות או של תנאי שימוש.
